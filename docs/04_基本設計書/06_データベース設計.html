6.3 共通設計方針

  • 主キー: id は BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY で統一する（T-21のみ key TEXT を主キーとする、Keirekiと同方針）。
  • タイムスタンプ: created_at / updated_at は TIMESTAMPTZ NOT NULL DEFAULT now() で全テーブルに付与する。
  • コード値（role, format, status, mode, type, kind, scope_type）はCHECK制約で許容値を担保する。
  • JSONB項目（options, correct_answer, response, question_order, findings, weak_questions等）は、詳細設計書でスキーマ（フィールド定義）を定める。
  • スキーマ定義は backend/database.py（SCHEMA定義）に集約し、テーブル定義書を docs/ で管理する。

各テーブルのカラム詳細（型・NULL可否・制約・既定値の全定義）は詳細設計書に委ねる。

RLS方針: 全テーブルでRow Level Security（RLS）を有効にする（ALTER TABLE ... ENABLE ROW LEVEL SECURITY;）。アプリケーションは asyncpg で直接接続するため通常アクセスの権限判定（3章のRBAC・オーナー/共同編集者判定プロジェクトのローカルロール判定）はAPI層で行うが、Supabaseの他経路（PostgREST等）からの意図しない参照を遮断する多層防御として全テーブルRLSを必須とする（Keirekiと同方針）。
