4.2 画面遷移図

共通レイアウト: 左サイドバー（メニュー: マイ学習、教材一覧・検索、教材編集[オーナー・共同編集者、またはプロジェクトの管理者・編集者プロジェクトの管理者・編集者を持つ教材がある場合のみ表示]、プロジェクト作成[全員に常時表示]、個人学習レポート、配信設定[プロジェクト・教材の有無や管理者かどうかによらず全員に常時表示。v1.42でこの位置に移動]／管理者メニュー: プロジェクト管理[自分が管理者であるプロジェクトがある場合のみ表示]、受講状況ダッシュボード、配信設定、組織管理、管理[adminのみ表示]）＋ ヘッダー（システム名、ユーザー名/アバター/ロールバッジ、ログアウト）。組織管理（S-07）はv1.5で廃止した。認証ガードは frontend/src/App.tsx で行い、未認証時は S-01 へ、権限外パスへのアクセス時は S-02 へ誘導する。フォーム部品はKeirekiと同様に自作の共通UIコンポーネント（frontend/src/components/ui/）に統一する。

各画面の具体的なレイアウト・UI項目は画面モックアップ「03_画面モックアップ/」を参照のこと。以下では各画面の設計概要のみ記す。

4.3 S-01 ログイン

  • 表示項目: システム名（社内学習管理システム Manabi）、「Googleでログイン」ボタン、@kogasoftware.com アカウントのみ利用可の旨、研修サンプルである旨の注記。
  • 操作: ボタン押下で A-01 へ遷移しGoogle OAuth 2.0フローを開始する。認証エラー時は本画面にエラーメッセージを表示する。

4.4 S-02 マイ学習

  • 表示項目: サマリー（必修教材受講率、期限が近い必修教材件数、任意教材受講済み件数、直近の受講日）、「期限が近い必修教材」の強調表示パネル、必修教材一覧、任意教材一覧。各教材カードに進捗バー・必修/任意バッジ・期限を表示。
  • 操作: A-39（マイ学習一覧取得）で必修・任意それぞれの進捗付き一覧を取得。「続きから受講」「受講を開始」「復習する」「反復演習する」等のボタンから S-04 へ遷移する。
  • 任意教材一覧の対象範囲（F-31）: 招待制プロジェクトの任意教材はプロジェクトメンバーであれば自動的に含める。全社Wiki（is_company_wide=true）所属の任意教材は、受講者本人がS-03で「マイ学習に追加」した教材のみを含める（T-30 my_learning_registrations）。必修教材は登録の有無によらず常に表示する。
  • 学習履歴（F-31）: 登録状態を問わず、T-12 enrollment_progressの行が存在する（少しでも着手した）教材を横断的に確認できる絞り込み・タブを別途設ける。マイ学習登録は「これから計画的に取り組む」ためのものであるのに対し、学習履歴は「過去に触れた記録」を後から見返すためのもので、目的が異なる。

4.5 S-03 教材一覧・検索

  • 検索パネル（開閉式）: キーワード（教材名・見出し名・コース名#タグ）／タグチップ（クリックで絞り込み）／区分（必修/任意）のプルダウン、「未受講のみ表示」「自分が受講対象の教材のみ表示」チェックボックス。
  • 一覧テーブル列: 教材（タイトル＋章数・ページ数・問題種別・問題数）／コースタグ（複数付与可）／区分／所要時間（目安）／更新日／操作（受講する・続きから受講・復習する・反復演習）。表示件数選択とページネーションを備える。
  • 操作: A-14（一覧・検索）を呼び出す。行選択・操作ボタンで S-04 へ遷移する。

4.6 S-04 教材受講S-04 教材受講：目次

  • タブ構成: 「通常受講」「目次」「反復演習」「誤答のみ抽出」の3タブ（4.1節ヘッダーに必修/任意バッジ・期限・単元位置章・ページ数を表示）。
  • 目次タブ: materials.attempt_scopeで定まる受験単位（教材全体/章/小見出し/ページ）ごとに独立した「前回の受験結果」パネルを表示（既定は教材全体で1枚。v1.17）。不合格時は再受験可否・残り回数を表示し、ドボン問題（is_critical）が原因の場合は該当設問名を理由として明示する。記述式回答のAI採点結果（採点中/採点済みの状態表示）、教材全体の進捗バー（完了ページ数/全ページ数）、教材全体の資料（特定ページに属さない添付ファイル・リンク。node_id未設定のT-09行。S-05「ファイル・リンク」タブで登録されたもの。v1.17追加）、章・小見出し・ページのツリー表示（各ページの完了/未完了マーク、種別バッジ〔説明／問題×N／説明＋問題×N／スコア記録〕）。ページ行を選ぶとS-16へ遷移する。「一時中断する」「続きから受講」ボタン。受験後アンケート（教材全体・該当する章に設置されている場合、対象の受験単位を完了した直後に表示。回答は任意でスキップ可。repeat_mode='once'なら2回目以降は表示しない。v1.17）。
  • 反復演習タブ: 実施履歴（正答数・所要時間）と「反復演習を開始」ボタン。合否には影響しない旨を明示。対象は教材内の全ページの問題。ドボン問題（is_critical）の判定は行わない（合否に関わらないモードのため）。
  • 誤答のみ抽出タブ: 出題範囲（この教材内の誤答のみ／全教材の誤答から出題）をラジオボタンで選択し「誤答問題を解く」ボタンで開始。
  • 操作: A-15（目次〔ツリー〕取得）、A-28（node_idを指定せずに呼び出し、教材全体の資料を取得）、A-40（受験開始）→ A-41（回答保存、都度呼び出しで中断・再開を実現）→ A-42（提出、AI採点トリガーを含む）→ A-43（結果取得）。反復演習・誤答抽出は A-40 の mode パラメータ、A-44（誤答抽出出題取得）で実現する。再受験はA-71（materials.retake_scopeに応じて全問または誤答のみを新しい試行に含める）、アンケート回答はA-72（v1.17）。

4.6a S-16 教材受講：ページ

  • 表示項目: パンくず（教材名／章／小見出し）、教材全体の進捗バー、説明文パネル（ページに説明文がある場合のみ表示）、設問カード（ページに問題がある場合のみ表示。回答済み・回答中・未解放の状態を視覚的に区別）。「目次へ戻る」「回答して次のページへ」ボタン。設問カードには種別に応じたUIを出す: 並び替え問題はドラッグ操作可能な項目リスト、スコア記録問題は数値入力欄＋「これまでの記録」表示（過去のresponse.score推移）。required=falseの設問は「スキップ」操作を表示。is_critical=trueの設問には「⚠ ドボン」バッジを表示する（v1.17）。
  • 操作: A-41（回答保存）、A-42（提出）。回答内容は都度保存され、中断してもS-04から同じページへ再開できる。

4.7b S-18 教材編集：Claude Code下書き作成

この画面は基本設計書v1.20で廃止されました。 F-27（AI教材作成アシスト。ブラウザ内対話生成）の廃止に伴い、この画面も廃止した。F-27はManabiのバックエンドがAnthropic Claude APIを直接呼び出す構造のため、利用のたびにManabi側で従量課金が発生していたが、F-05（Claude Code CLI連携）はClaude Code利用者本人の契約で課金され、Manabi側の運用コストが発生しない。両者が似た体験を提供する代替経路だったため、コストの発生しないF-05に一本化することとした。教材の作成・修正へのAI支援はすべてF-05経由で行う（8章参照）。S-14「＋新規教材を作成」は、この画面を経由せず空のS-05目次編集画面へ直接遷移する（v1.14以前の遷移に戻した）。画面ID・パス・関連API（A-68〜A-70）・関連テーブル（T-24, T-25）はいずれも欠番として保持する。

4.7c S-19 設問別の回答・結果一覧

  • 表示項目: パンくず（教材名／設問の所在）、対象設問の概要（設問文・種別・採点方式）、設問形式に応じた診断テーブル。単一選択/複数選択/並び替えは選択肢（または項目）ごとの回答数・割合と全体正答率、記述式/コード記述式は受講者ごとの回答内容・AI採点結果（grading_mode='manual'の未採点分は「未採点」バッジのみ、正誤の概念は表示しない）と全体正答率、score_logは受講者ごとの最新スコア・推移（例: 45→52→58）・最終記録日を表示する。各設問の末尾に、正答率が低い理由や誤答の傾向についての診断コメント（AI講評の集計、またはF-21のつまずき分析の抜粋）を表示する。

  • 表示項目: プロジェクト名・説明の入力欄、作成すると何が起きるかの説明（作成者が自動的にそのプロジェクトの管理者になる旨）、「自分が参加しているプロジェクト」一覧（プロジェクト名・自分のロール・状態〔進行中/停止。表示ラベルは「停止」だがAPI・DB上のenum値は'completed'のまま。停止中のプロジェクトも含めて全件表示し・S-12を開く操作。管理者ロールの行のみS-12への導線を有効化し、状態もその場で変更〔停止済みの再開を含む〕できる。この一覧はS-12（4.14節）のプロジェクト一覧表示と共通の部品である（v1.40））。
  • 操作: A-09（プロジェクト作成。作成者を project_memberships.role='admin' で自動登録。3.5節・5.25節参照）。「自分が参加しているプロジェクト」一覧はA-11をログインユーザーのuser_idで絞り込んで取得する。一覧上の状態変更はA-92を呼ぶ（v1.40）。「作成する」押下は即座にAPIを呼ばず、内容確認モーダルを1段階挟む（誤操作防止。v1.40）。
  • アクセス制御: 全員（誰でも新規作成できる。F-24）。サイドバー・ヘッダーに常時表示する。

4.14 S-12 プロジェクト管理

  • ヘッダー: 管理するプロジェクトの選択（自分が管理者であるプロジェクトが複数ある場合はプルダウンで切替。adminは全プロジェクトから選択可）。「管理者であるプロジェクトが実質1件（有効な状態のプロジェクトの管理者が1つだけ）」のときのみ自動的にその詳細へ遷移する。それ以外（0件、複数件、または管理者であるプロジェクトが停止中のみ等）の場合は、S-11と共通の「自分の全プロジェクト一覧」（プロジェクト名・ロール・状態〔進行中/停止〕・操作。管理者ロールの行のみ状態変更・詳細への遷移が可能）をまず表示する。従来は常に最初の管理対象プロジェクトへ自動遷移していたが、A-81の並び順（全社Wiki先頭固定）の影響で「複数プロジェクトを管理していると必ず全社Wikiが開く」という分かりにくさがあったため変更した（v1.40）。:projectId未指定時は、管理者であるプロジェクトの件数によらず（1件のみの場合も含む）常にS-11と共通の「自分の全プロジェクト一覧」（プロジェクト名・ロール・状態〔進行中/停止〕・操作。管理者ロールの行のみ状態変更・詳細への遷移が可能）をまず表示する。自動遷移は一切行わない。v1.40では「1件のみなら自動遷移」としていたが、1件しかない場合でも一覧を経由してから詳細に入りたいというユーザーフィードバックを受け、この自動遷移を撤回した（v1.41）。個別プロジェクトの詳細を開いているときはヘッダーに「一覧に戻る」導線を表示する。
  • 「自分の全プロジェクト一覧」の絞り込み・色分け: 既定では進行中のプロジェクトのみを表示し、「停止中のプロジェクトも表示する（N件）」チェックで停止中も含めた全件表示に切り替える。停止中の行は進行中と視覚的に区別できるよう淡色表示・状態バッジの色分け（進行中=緑、停止=グレー）にする（v1.42）。
  • タブ構成: 「プロジェクト情報」（名称・説明・状態の編集、作成日・作成者の表示、条件を満たす場合のみ有効化される「プロジェクトを削除」ボタン。5.32節参照）、「メンバー管理」（氏名・全社ロール・プロジェクトロール・参加日の一覧、ロール変更、社員選択による追加、削除。唯一の管理者は削除・降格不可）、「教材の共有」（このプロジェクトに紐づく公開済み教材ごとの共有先プロジェクト設定・申請〔下書き教材は共有不可〕に加え、他プロジェクトからこのプロジェクト宛ての共有リクエストの確認・承認・却下も同じタブで行う。5.27節）。
  • 操作: A-10（プロジェクト情報更新）、A-11（メンバー一覧取得）、A-12（メンバー追加・ロール設定）、A-13（メンバー削除・ロール変更）、A-59〜A-61（教材のプロジェクト間共有設定。5.27節参照）、A-92（一覧からの状態のみの変更・停止済みプロジェクトの再開。v1.40）、A-93（プロジェクトの完全削除。v1.42、5.32節）。
  • アクセス制御: 対象プロジェクトの管理者、または admin（3.5節）。

4.14a S-15 プロフィール編集

  • 表示項目: 現在のアイコン画像（独自アップロード分があればそれ、無ければGoogleプロフィール画像）、表示名の入力欄、メールアドレス（参照専用）、システムロールのバッジ表示、所属プロジェクト一覧、招待されているプロジェクト一覧（承諾・辞退操作。F-24）。
  • 操作: 表示名を編集して保存するとA-75（PUT /api/auth/me）を呼ぶ。アイコンを選択するとA-76（POST /api/auth/me/icon/upload-url）で署名付きURLを取得してアップロードし、A-75で確定する。「Googleの画像に戻す」でA-77（DELETE /api/auth/me/icon）を呼ぶ。所属プロジェクト一覧はA-11（user_id=自分, status='active'）、招待一覧はA-11（user_id=自分, status='invited'）と応答用のA-67を使用する（5.25節）。
  • アクセス制御: 全員（自分自身の情報のみ操作可）。
  • 変更履歴の扱い: 表示名・アイコンの変更はT-08 material_revisions（教材専用）の対象外であり、専用の履歴保持は行わない（変更前の値を追跡する要求が無いため）。
