1. このドキュメントの目的

Manabiには、教材の章・ページ・設問をプレーンテキスト（YAMLフロントマター＋Markdown見出し階層）として 読み書きできるAPIが用意されている（A-16・A-19・A-20）。Claude Codeにこの手順を頼めば、 ブラウザでManabiの画面を開かずに、チャットでの指示だけで教材を新規作成・編集できる。

依頼の例: 「Manabi教材を作って。タイトルは『Git入門』、プロジェクトは新人研修プロジェクトで、 第1章にコミットの基本を説明するページと、確認問題を1問（単一選択）入れて」のように、自然文で依頼すればよい。 Claude Code側は.claude/skills/manabi-material/SKILL.mdのスキル定義に従い、本書と同じ手順で API呼び出しを組み立てる。

2. 事前準備（初回のみ）

ManabiのAPIを呼ぶには認証済みのCLIトークンが必要。~/.config/Manabi/credentialsに 保存済みのトークンが無い場合、Claude Code自身はブラウザでのGoogle認証を完結できないため、 ユーザー本人が以下を実行する。 

python cli/manabi_login.py

ブラウザが自動で開き、Googleアカウント（kogasoftware.com）でログインを求められる。 成功すると~/.config/Manabi/credentials（JSON: {"manabi_url": "...", "token": "..."}、 有効期限90日）が保存され、以後Claude Codeがこのファイルからトークンを読んで使う。

本番環境に対して使う場合は別手順。 既定ではローカル環境（http://localhost:5177）を対象にする。本番環境 （https://manabi-elearning.fly.dev）に対して直接教材を作成・編集したい場合は、 MANABI_URLを指定してログインし直す必要がある（ 参考資料_本番環境運用手順.html 6章参照）。 ログイン情報の保存先は環境によらず1箇所のみのため、本番向けにログインし直すとローカル向けの トークンは上書きされる。

3. 教材作成の全体の流れ

白紙の新規教材を作る場合、以下の3ステップで完結する（Manabi画面は一切使わない）。

手順API内容
① 新規作成A-16 POST /api/materialsタイトル・所属プロジェクトを指定して空の教材を1つ発行する。レスポンスのidを控える。
② 取得A-19 GET /api/materials/{id}/sourceフロントマターのみの空の教材ソースを取得する。
③ 編集・保存A-20 PUT /api/materials/{id}/source取得したテキストに章・ページ・設問を書き足し、全体をそのまま保存する（部分更新ではなく全置換）。

既存教材を編集したい場合は①を省略し、②→③だけを行う（対象教材のIDが分からない場合はGET /api/materialsで一覧から探す）。

A-20は目次構造全体の全置換。 取得したソースの一部だけを書き換えて送り返すこと。必要な変更以外の章・ページを勝手に削除しない （送らなかった部分は「削除された」とみなされる）。

4. フロントマター（教材メタデータ）の書式

教材ソースの先頭は---で囲んだYAMLのフロントマター。

---
title: 教材タイトル
description: 説明文（省略可）
tags: ["タグ1", "タグ2"]
status: draft  # draft（下書き）| published（公開）
attempt_scope: material  # material | chapter | section | page（受験の単位）
retake_scope: all  # all（全問）| wrong_only（誤答のみ）
pass_score_pct: 70  # 合格基準スコア（%）。省略・nullなら「合格基準なし＝常に合格」
retake_allowed: true  # 再受験を許可するか
retake_limit: null  # 再受験回数の上限。nullなら無制限
default_feedback_style: show_answer  # show_answer | review_only | hint_only
grading_mode: ai  # 記述式/コード記述式のAI採点を使うかどうかの既定値（ai | manual）
---
項目必須内容
title必須教材タイトル。
project_id新規作成時のみ省略すると全社Wikiになる。既存教材の場合は元のプロジェクトと一致している必要がある（変更したい場合はManabi画面のA-17を使う）。
status任意（既定draft）publishedにすると受講対象者に公開される。
attempt_scope任意（既定material）合否判定・提出の単位。章ごとに区切って合否を出したい場合はchapterにする。
retake_scope任意（既定all）wrong_onlyにすると、再受験時は前回不正解だった設問だけが出題され、正解済みの設問はそのまま正解として繰り越される。
pass_score_pct任意この％以上で合格。省略時（null）は合格基準なし＝提出すれば常に合格扱いになり、再受験設定に従って何度でも解き直せる。
retake_allowed / retake_limit任意（既定true / 無制限）再受験の可否と回数上限。上限に達すると再受験できなくなる（合格済みスコープは、合格基準を設定している場合に限りそもそも再受験対象外になる）。
default_feedback_style任意記述式・コード記述式のAI講評の見せ方の既定値。設問ごとにfeedback_styleで上書きできる。
grading_mode任意（既定ai）記述式・コード記述式の採点方式の既定値。設問ごとに上書きできる（6章参照）。

5. 目次構造（章・小見出し・ページ）の書き方

フロントマターに続けて、Markdownの見出し記号で目次階層を表現する。

見出し意味
#章（chapter）
##小見出し（section、省略可。章の直下にページを置いてもよい）
###ページ（page）
章タイトルに「第1章」等の番号を含めない。 画面側が章の並び順から自動的に「第N章 」を付けて表示するため、タイトル自体にも書くと 「第1章 第1章 はじめに」のように二重表示になる。章タイトルは番号を除いた文言のみ （例: # はじめに）にする。

既存ページ・章を更新する場合は、見出し行の直後に<!-- node:123 -->を付ける （無ければ新規ノードとして作成される）。ページには任意で<!-- format:markdown -->／ <!-- format:html -->（省略時はフロントマターの既定値）、出題プールを使う場合は <!-- quiz_mode:pool -->と<!-- pool_draw_count:N -->を付けられる。

ページの本文は説明文（Markdown/HTML）と、それに続く```question```フェンスブロック （0個以上）を自由に組み合わせられる。

本文中に見出し記号（#〜###）を書く場合は\でエスケープする。 コードブロック内のシェルコメント\# ...なども含む。エスケープせずそのまま書くと、 その行が実際の章・小見出し・ページの区切りと誤認識され、意図しない場所でページが分割されてしまう。 既存教材をA-19で取得した本文には書き出し時に自動でエスケープ済みのため気にしなくてよいが、 新規に本文を書き起こす場合は自分でエスケープが必要。

6. 設問（問題）ブロックの書き方

```question```フェンス内はYAMLで、種別（type）ごとに必須項目が異なる。

type用途必須項目
single単一選択options（配列）, correct_answer（optionsの中の1つの文字列）
multi複数選択options（配列）, correct_answer（配列）
reorder並び替えcorrect_answer（2件以上の配列、正しい順序）
free_text記述式scoring_criteria（AI採点の基準文）
codeコード記述式scoring_criteria, code_language（例: python）
score_log記録型（自己申告の数値記録、正誤判定なし）無し。score_unit（例: "点", "秒"）は任意項目（省略可、問題文側で単位を指定してもよい）。is_criticalは設定不可。

共通の任意項目:

項目内容
id既存問題を更新する場合の問題ID。新規なら省略。
prompt問題文。必須。
required / counted回答必須・合否算入の組み合わせで実質3状態になる（下表参照）。
is_critical既定false。trueにすると正誤に関わらず不正解だと以降のページに進めない「ドボン問題」になる。countedがfalseの設問（記録・任意）では判定自体が発生しないため同時指定は無意味。
feedback_style省略時はページ・教材の既定値を継承。
pool_groupquiz_mode:poolのページでの出題グループ番号。
grading_modefree_text/codeのみ。aiまたはmanual。省略時は教材の既定値（フロントマターのgrading_mode）を継承。

required / counted の3状態

状態設定意味
必須（既定）required: true, counted: true回答必須、スコア・合否判定に算入する。
記録required: true, counted: false回答は必須だが、AIによる採点・フィードバック自体は行われても合否には反映しない。「回答は必須で書かせたいが合否には関係ない設問」を作りたい場合に使う。
任意required: false, counted: false回答をスキップでき、合否にも反映されない。
required: false, counted: trueという組み合わせは意味を成さないため使わない。 設問文に「採点対象外」等と書くだけでは何も変わらない（実際の判定はこの2項目でのみ決まる）ので注意。

7. 実践例：簡単な教材を1つ作ってみる

「新人研修プロジェクトに、Python変数の教材を1つ作って、確認問題を1問入れて」と依頼した場合、Claude Codeは概ね以下の手順で進める。

① 新規作成（A-16）

curl -s -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"project_id": 8, "title": "Python入門：変数"}' \
  "$URL/api/materials"
# → {"id": 42, ...}

② 取得（A-19）

curl -s -H "Authorization: Bearer $TOKEN" "$URL/api/materials/42/source"

③ 章・ページ・設問を書き足して保存（A-20）

---
id: 42
project_id: 8
title: Python入門：変数
status: published
attempt_scope: material
retake_scope: all
default_feedback_style: show_answer
grading_mode: ai
---

# Python入門

## 変数と型

### 変数の宣言
<!-- format:markdown -->

Pythonの変数には型宣言が不要です。`x = 1`と書くだけで変数`x`が作られます。

```question
type: single
prompt: 次のうち、Pythonの変数名として正しいものはどれか
options:
  - "1abc = 1"
  - "abc_1 = 1"
  - "abc-1 = 1"
correct_answer: "abc_1 = 1"
```
curl -s -X PUT -H "Authorization: Bearer $TOKEN" -H "Content-Type: text/plain" \
  --data-binary @material.md "$URL/api/materials/42/source"

保存が成功すると、更新後のソース（実際に採番されたノードID<!-- node:xxx -->付き）が そのままレスポンスとして返る。以後この教材をさらに編集する場合は、このノードID付きのソースを ベースに変更すればよい。

8. 画像の埋め込み

本文に画像を貼りたい場合は![説明](attachment:123)という記法を使う（123は下記手順で アップロードした添付ファイルのID）。表示のたびにその時点で有効なURLへ自動的に解決されるため、 Base64化して直接貼り付ける必要はない。

  1. アップロード先URLを発行する（A-27）: 
    curl -s -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"filename": "screenshot.png", "mime_type": "image/png", "size_bytes": 12345}' \
  "$URL/api/materials/{id}/attachments/upload-url"
    レスポンスのupload_url・storage_keyを控える。
  2. 発行されたURLへ画像本体をアップロードする: 
    curl -s -X PUT --data-binary @screenshot.png "$UPLOAD_URL"
    （本番はSupabase StorageのURLがそのまま返るため$URLを付けず$UPLOAD_URLだけで叩く。 ローカル開発では$URL＋upload_urlの組み合わせになる）
  3. 添付として登録し、IDを取得する（A-29。node_idは画像を貼りたいページのノードID）: 
    curl -s -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"node_id": 456, "kind": "file", "storage_key": "'"$STORAGE_KEY"'", "filename": "screenshot.png", "mime_type": "image/png", "size_bytes": 12345}' \
  "$URL/api/materials/{id}/attachments"
    レスポンスのidを使い、本文に![説明](attachment:{id})と書いてA-20で保存する。

外部サイトへのリンクを貼りたいだけの場合（画像でなく参照用リンク）はこの手順は不要で、通常のMarkdownリンク[表示文言](https://...)をそのまま本文に書けばよい。

9. よくあるエラーと対処

状況原因・対処
A-20が422を返すdetailにパースエラー内容が入っている（フロントマター不備・見出し順序違反・問題ブロックの必須項目不足など）。内容を確認して修正し再送する。
401エラーCLIトークンが無い、または失効している（90日）。python cli/manabi_login.pyで再ログインする。
403エラー指定したproject_idの編集者以上（またはシステムadmin）の権限が無い。所属プロジェクトが分からない場合はGET /api/projectsで一覧を確認する。
「第1章 第1章 …」のように章番号が二重表示される章タイトルに自分で番号を書いてしまっている。5章の注意を参照し、タイトルから番号を除く。
本文中の見出し記号でページが意図せず分割される本文中の#〜###で始まる行（コードコメント含む）が\でエスケープされていない。5章の注意を参照。
