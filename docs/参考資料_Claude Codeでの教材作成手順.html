Claude Codeでの教材作成手順

社内学習管理システム（Manabi）— Claude Code CLI連携（F-05）を使った教材の新規作成・編集手順

作成日: 2026-09-11 版数: 1.1 作成: コガソフトウェア株式会社

本ドキュメントは新人社員向けAI開発研修のサンプル成果物です。 Manabi画面を一切開かずに、Claude Codeへの指示だけで教材（章・ページ・設問）を作成・編集する方法をまとめる。 2026-09-14からはMCP（Model Context Protocol）連携が使えるようになり、SKILL.mdファイルの配布や CLIトークンの手動発行（manabi_login.py実行）が不要になったため、本書はMCP連携のみを 手順として説明する（各自の端末にファイルを保存・配布してもらう方式は、この移行に伴い廃止した）。

1. このドキュメントの目的

Manabiには、教材の章・ページ・設問をプレーンテキスト（YAMLフロントマター＋Markdown見出し階層）として 読み書きできるAPI（A-16・A-19・A-20）と、それをClaude Code等のAIから直接呼べるMCPサーバーが用意されている。 Claude Codeにこの手順を頼めば、ブラウザでManabiの画面を開かずに、チャットでの指示だけで 教材を新規作成・編集できる。

依頼の例: 「Manabi教材を作って。タイトルは『Git入門』、プロジェクトは新人研修プロジェクトで、 第1章にコミットの基本を説明するページと、確認問題を1問（単一選択）入れて」のように、自然文で依頼すればよい。 2章の準備が済んでいれば、Claude CodeはMCPサーバーが提供する道具 （create_material・get_material_source・put_material_source等）を 自動的に使い分けて、本書と同じ手順でAPI呼び出しを組み立てる。

2. 事前準備（初回のみ）

2.1 APIキーを発行する

Manabiにブラウザでログインし、次のいずれかからAPIキー（CLIトークン）を発行する。

  • 初回ログイン直後に表示される案内画面の「発行する」ボタン
  • いつでも: プロフィール画面（/profile）の「APIキー（Claude Code連携）」パネルの「発行する」ボタン

発行された鍵とMCPサーバーの接続先URL（{ManabiのURL}/mcp）がその場で表示される （鍵はこのとき限りしか表示されないため、その場でコピーする）。

鍵は他人に見せない・会話やチャットに貼り付けない。 発行した鍵は、次の2.2節のコマンドの引数として、自分の端末のターミナルで直接使う。 Claude Codeとの会話（チャットのメッセージ）には絶対に貼り付けないこと——会話ログとして 記録が残るため、読める人がいれば誰でもその鍵を使えてしまう。

2.2 Claude CodeにMCPサーバーを登録する

自分の端末のターミナルで、発行された鍵を使って1回だけ登録する（1人・1台につき初回のみでよい）。

claude mcp add --transport http manabi {ManabiのURL}/mcp --header "Authorization: Bearer {発行された鍵}"

ローカル環境なら{ManabiのURL}はhttp://localhost:5177、本番環境なら https://manabi-elearning.fly.devになる（発行画面に表示された接続先をそのまま使えばよい）。 登録は一度行えば、以後Claude Codeを開き直しても覚えている。新しいセッションを開けば、 登録したMCPサーバーの道具（ツール）が自動的に使えるようになる（セッション内で/mcpと 打つと接続状況を確認できる）。

鍵は使い回さず、必要になったら都度発行する。 「発行する」を押すたびに新しい鍵が発行される（古い鍵は自動では失効しない）。PCを変える・ 鍵が漏れた等の理由で無効化したい場合は、プロフィール画面の「発行済みの鍵」一覧から 対象の鍵の「失効する」を押せばよい（鍵そのものを提示する必要はない）。

3. 教材作成の全体の流れ

白紙の新規教材を作る場合、Manabi画面は一切使わずに完結する。2章の準備が済んでいれば、 以下の3ステップはClaude Codeが対応する道具（ツール）を自動的に呼び出す形で進み、 利用者が個々のAPIを意識する必要はない。

手順MCPの道具API内容
① 新規作成create_materialA-16 POST /api/materialsタイトル・所属プロジェクトを指定して空の教材を1つ発行する。
② 取得get_material_sourceA-19 GET /api/materials/{id}/sourceフロントマターのみの空の教材ソースを取得する。
③ 編集・保存put_material_sourceA-20 PUT /api/materials/{id}/source取得したテキストに章・ページ・設問を書き足し、全体をそのまま保存する（部分更新ではなく全置換）。

既存教材を編集したい場合は①を省略し、②→③だけを行う（対象教材のIDが分からない場合は search_materials／GET /api/materialsで一覧から探す）。

③は目次構造全体の全置換。 取得したソースの一部だけを書き換えて送り返すこと。必要な変更以外の章・ページを勝手に削除しない （送らなかった部分は「削除された」とみなされる）。
MCPで対応していない操作。 教材の公開/非公開切り替え・アーカイブ・削除・配信設定の変更・画像の添付（8章参照）は MCPの道具に含まれていない。これらを頼むと、Claude Codeはget_material_edit_urlを 使ってWeb画面の編集URLを案内するので、そのURLをブラウザで開いて操作する。

4. フロントマター（教材メタデータ）の書式

教材ソースの先頭は---で囲んだYAMLのフロントマター。

---
title: 教材タイトル
description: 説明文（省略可）
tags: ["タグ1", "タグ2"]
status: draft  # draft（下書き）| published（公開）
attempt_scope: material  # material | chapter | section | page（受験の単位）
retake_scope: all  # all（全問）| wrong_only（誤答のみ）
pass_score_pct: 70  # 合格基準スコア（%）。省略・nullなら「合格基準なし＝常に合格」
retake_allowed: true  # 再受験を許可するか
retake_limit: null  # 再受験回数の上限。nullなら無制限
default_feedback_style: show_answer  # show_answer | review_only | hint_only
grading_mode: ai  # 記述式/コード記述式のAI採点を使うかどうかの既定値（ai | manual）
---
項目必須内容
title必須教材タイトル。
project_id新規作成時のみ省略すると全社Wikiになる。既存教材の場合は元のプロジェクトと一致している必要がある（変更したい場合はManabi画面のA-17を使う）。
status任意（既定draft）publishedにすると受講対象者に公開される。
attempt_scope任意（既定material）合否判定・提出の単位。章ごとに区切って合否を出したい場合はchapterにする。
retake_scope任意（既定all）wrong_onlyにすると、再受験時は前回不正解だった設問だけが出題され、正解済みの設問はそのまま正解として繰り越される。
pass_score_pct任意この％以上で合格。省略時（null）は合格基準なし＝提出すれば常に合格扱いになり、再受験設定に従って何度でも解き直せる。
retake_allowed / retake_limit任意（既定true / 無制限）再受験の可否と回数上限。上限に達すると再受験できなくなる（合格済みスコープは、合格基準を設定している場合に限りそもそも再受験対象外になる）。
default_feedback_style任意記述式・コード記述式のAI講評の見せ方の既定値。設問ごとにfeedback_styleで上書きできる。
grading_mode任意（既定ai）記述式・コード記述式の採点方式の既定値。設問ごとに上書きできる（6章参照）。

5. 目次構造（章・小見出し・ページ）の書き方

フロントマターに続けて、Markdownの見出し記号で目次階層を表現する。

見出し意味
#章（chapter）
##小見出し（section、省略可。章の直下にページを置いてもよい）
###ページ（page）
章タイトルに「第1章」等の番号を含めない。 画面側が章の並び順から自動的に「第N章 」を付けて表示するため、タイトル自体にも書くと 「第1章 第1章 はじめに」のように二重表示になる。章タイトルは番号を除いた文言のみ （例: # はじめに）にする。

既存ページ・章を更新する場合は、見出し行の直後に<!-- node:123 -->を付ける （無ければ新規ノードとして作成される）。ページには任意で<!-- format:markdown -->／ <!-- format:html -->（省略時はフロントマターの既定値）、出題プールを使う場合は <!-- quiz_mode:pool -->と<!-- pool_draw_count:N -->を付けられる。

ページの本文は説明文（Markdown/HTML）と、それに続く```question```フェンスブロック （0個以上）を自由に組み合わせられる。

本文中に見出し記号（#〜###）を書く場合は\でエスケープする。 コードブロック内のシェルコメント\# ...なども含む。エスケープせずそのまま書くと、 その行が実際の章・小見出し・ページの区切りと誤認識され、意図しない場所でページが分割されてしまう。 既存教材をA-19で取得した本文には書き出し時に自動でエスケープ済みのため気にしなくてよいが、 新規に本文を書き起こす場合は自分でエスケープが必要。

6. 設問（問題）ブロックの書き方

```question```フェンス内はYAMLで、種別（type）ごとに必須項目が異なる。

type用途必須項目
single単一選択options（配列）, correct_answer（optionsの中の1つの文字列）
multi複数選択options（配列）, correct_answer（配列）
reorder並び替えcorrect_answer（2件以上の配列、正しい順序）
free_text記述式scoring_criteria（AI採点の基準文）
codeコード記述式scoring_criteria, code_language（例: python）
score_log記録型（自己申告の数値記録、正誤判定なし）無し。score_unit（例: "点", "秒"）は任意項目（省略可、問題文側で単位を指定してもよい）。is_criticalは設定不可。

共通の任意項目:

項目内容
id既存問題を更新する場合の問題ID。新規なら省略。
prompt問題文。必須。
required / counted回答必須・合否算入の組み合わせで実質3状態になる（下表参照）。
is_critical既定false。trueにすると正誤に関わらず不正解だと以降のページに進めない「ドボン問題」になる。countedがfalseの設問（記録・任意）では判定自体が発生しないため同時指定は無意味。
feedback_style省略時はページ・教材の既定値を継承。
pool_groupquiz_mode:poolのページでの出題グループ番号。
grading_modefree_text/codeのみ。aiまたはmanual。省略時は教材の既定値（フロントマターのgrading_mode）を継承。

required / counted の3状態

状態設定意味
必須（既定）required: true, counted: true回答必須、スコア・合否判定に算入する。
記録required: true, counted: false回答は必須だが、AIによる採点・フィードバック自体は行われても合否には反映しない。「回答は必須で書かせたいが合否には関係ない設問」を作りたい場合に使う。
任意required: false, counted: false回答をスキップでき、合否にも反映されない。
required: false, counted: trueという組み合わせは意味を成さないため使わない。 設問文に「採点対象外」等と書くだけでは何も変わらない（実際の判定はこの2項目でのみ決まる）ので注意。

7. 実践例：簡単な教材を1つ作ってみる

「新人研修プロジェクトに、Python変数の教材を1つ作って、確認問題を1問入れて」と依頼する。 このひとことをそのままチャットに送るだけでよい。

内部の流れ: Claude Codeはcreate_material（新規作成）→ get_material_source（空の教材の取得）→4〜6章のルールに沿って章・ページ・設問を 考えて書き足す→put_material_source（保存）の順に道具を呼び出し、完了したら 結果を報告する。利用者はAPI・トークンの類を一切意識しない。

上記の依頼に対し、Claude Codeがput_material_sourceに渡すテキスト（＝実際に 保存される教材ソース）はおおむね次のようになる（4〜6章の書式の実例として参考にする）。 

---
title: Python入門：変数
status: published
attempt_scope: material
retake_scope: all
default_feedback_style: show_answer
grading_mode: ai
---

# Python入門

## 変数と型

### 変数の宣言

Pythonの変数には型宣言が不要です。`x = 1`と書くだけで変数`x`が作られます。

```question
type: single
prompt: 次のうち、Pythonの変数名として正しいものはどれか
options:
  - "1abc = 1"
  - "abc_1 = 1"
  - "abc-1 = 1"
correct_answer: "abc_1 = 1"
```

保存が成功すると、実際に採番されたノードID（<!-- node:xxx -->）付きの ソースが返る。以後この教材をさらに編集する場合、Claude Codeはget_material_sourceで このノードID付きのソースを取得してから変更する。

8. 画像の埋め込み

画像のアップロードはMCPの道具に含まれていない（3章のMCPで対応していない操作を参照）。 次の手順でWeb画面から行う。

  1. 対象ページの編集画面（S-17教材編集：ページ編集）を開く（Claude Codeに「編集画面のURLを教えて」と 頼めばget_material_edit_urlで案内してもらえる）。
  2. 「このページの添付ファイル・リンク」から画像ファイルを選択してアップロードする。
  3. 一覧に追加された添付のidを確認する。

本文中で画像を表示したい位置に![説明](attachment:123)という記法を使う（123は 上記でアップロードした添付ファイルのID）。表示のたびにその時点で有効なURLへ自動的に解決されるため、 Base64化して直接貼り付ける必要はない。この本文をClaude Codeに伝えれば、put_material_source で保存してもらえる。

外部サイトへのリンクを貼りたいだけの場合（画像でなく参照用リンク）はこの手順は不要で、通常のMarkdownリンク[表示文言](https://...)をそのまま本文に書けばよい。

9. よくあるエラーと対処

状況原因・対処
Claude Codeが「manabiの道具が見つからない」「MCPサーバーに接続できない」と言う2.2節のclaude mcp addが済んでいないか、登録前のセッションのままになっている。セッション内で/mcpと打って接続状況を確認し、繋がっていなければ新しいセッションを開き直す（新しいセッションの開き方はClaude Codeのコマンドパレットから「Claude Code: Open in New Tab」等）。
本番のはずがローカルに（またはその逆）繋がっている登録したMCPサーバーの接続先（2.2節のURL）を確認する。ローカル・本番それぞれ別名で登録している場合は、依頼時に「manabi-prodを使って」のようにサーバー名を明示する。
MCP経由の道具呼び出しがエラーになる権限不足（対象教材の編集者以上でない）・存在しない教材IDの指定など、原因はput_material_sourceと同様。Claude Codeにエラー内容を確認してもらい、対象や依頼内容を見直す。
put_material_sourceがエラーを返すフロントマター不備・見出し順序違反・問題ブロックの必須項目不足など、パースエラーの内容がエラーメッセージに含まれる。内容を確認して修正し再送する。
401エラーAPIキーが失効している。プロフィール画面から再発行し、2.2節の手順で登録し直す。
403エラー指定したproject_idの編集者以上（またはシステムadmin）の権限が無い。所属プロジェクトが分からない場合は「参加しているプロジェクトを教えて」のようにClaude Codeに確認してもらう。
「第1章 第1章 …」のように章番号が二重表示される章タイトルに自分で番号を書いてしまっている。5章の注意を参照し、タイトルから番号を除く。
本文中の見出し記号でページが意図せず分割される本文中の#〜###で始まる行（コードコメント含む）が\でエスケープされていない。5章の注意を参照。
