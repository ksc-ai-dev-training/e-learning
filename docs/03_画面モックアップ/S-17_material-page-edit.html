ブランチを作成する

作業を始める前に、必ず main から新しいブランチを作成します。

git checkout -b feature/add-login
  • コミットメッセージは変更内容が分かるように書く
  • 差分（diff）はマージ前に必ず自分で見直す

問題（このページでは未使用）

「問題を含める」にチェックすると、下の例（第2章「プルリクエストを作成する」ページ）と同じ設問編集フォームがここに展開されます。

プールを選ぶと「プール内の設問数」「1回あたりの出題数」を追加で設定できます（大きな問題バンクから毎回一部だけ出題したい場合。例: 章末に50問プールを用意し、受講のたびランダムに5問）。
※ 参考として、「説明＋問題」ページ（第2章「プルリクエストを作成する」）を開いた場合の問題編集フォームを以下に例示します。種別は単一選択・複数選択・並び替え・記述式・コード記述式・スコア記録から選べます。コード記述式はAIがコードを実行せず読解して採点するため、数式処理・辞書操作等、実行結果をAIが読解のみで推論しやすい教育用の課題を想定してください。
設問1（単一選択）
回答一覧

※ 単一選択・複数選択は「正解にチェック」した内容（correct_answer）と回答を直接照合するため、採点にAIは使いません。

不正解だと受験単位（S-05で設定）が正答率によらず不合格になります
設問2（記述式）⚠ ドボン
回答一覧

※ 記述式・コード記述式は、この基準を参照して採点します。基準そのものは人が設定しますが、最終判定は下の「採点方式」でAIまたはプロジェクト担当者のどちらかに委ねられます。配点は設けず、教材全体の正答率（正解した設問数／全設問数）のみで合否を判定します。

「手動採点」を選ぶと、この設問はAIによる正誤判定を行わずS-19「回答一覧」で担当者が採点します。AIはその結果をF-21のつまずき分析にのみ利用します。
採点方式が「AI自動採点」の場合のみ有効です。この設問だけ教材の既定と違うスタイルにしたい場合に選びます。
設問3（並び替え）
回答一覧
⠿ 1. 作業ブランチを作成する
⠿ 2. 変更をコミットする
⠿ 3. リモートへpushする
⠿ 4. プルリクエストを作成する

受講側ではこの項目がシャッフルされた状態で表示され、受講者がドラッグで並び替えて回答します。採点は正解の並びと回答順序の完全一致で判定し、AIは使いません。

設問4（スコア記録）
回答一覧
正解・不正解の概念を持たない設問です。受講者が数値を自己申告で入力し、記録として積み上がります（反復演習と組み合わせて推移を追う想定）。正答率の計算には含めず、ドボン問題にも設定できません。AI個人フィードバックでスコアの推移コメントが本人に届きます。
