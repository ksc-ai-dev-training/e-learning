1. このドキュメントの目的

本システムをローカル端末で動く状態にするまでの手順をまとめる。 実装は画面単位（縦切り）で進めるため、本書も実装の進行に合わせて随時更新する （CLAUDE.mdの「実装フェーズの進め方」参照）。新しい起動手順・設定項目が増えたら、 その回の実装と同じタイミングで本書にも反映すること。

2. 前提環境

ソフトウェアバージョン必須備考
Windows10 / 11必須 
Python3.12以上必須バックエンド（FastAPI）。本プロジェクトでは3.14で動作確認済み
Node.js22以上必須フロントエンド（Vite）。本プロジェクトでは24で動作確認済み
PostgreSQL16必須Dockerコンテナで用意する（→4章）
Docker Desktop—必須WSL2の有効化が必要。現状はDocker前提で、ローカルインストール版は未整備（→4章）

3. 構築手順（初回のみ）

3.1 リポジトリの取得

git clone https://github.com/ksc-ai-dev-training/e-learning.git
cd e-learning

3.2 バックエンドの依存インストール

cd backend
py -3.12 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
cd ..

3.3 フロントエンドの依存インストール

cd frontend
npm install
cd ..

3.4 .envの作成

copy .env.example .env

設定項目の意味は5章を参照。ローカル開発ではDEV_AUTH=1（既定）のまま変更不要。

4章を参照。

4. データベースの用意

4.1 Docker を使う場合（検証済み）

Docker Desktopのエンジンが起動していることを確認してから、コンテナを作成する （.envのDB_PORTと一致させること。既定値は55433）。 

docker run -d --name manabi-db ^
  -e POSTGRES_PASSWORD=manabi -e POSTGRES_USER=manabi -e POSTGRES_DB=manabi ^
  -p 55433:5432 postgres:16

2回目以降は次のコマンドで再開する。

docker start manabi-db
テーブル定義（T-01）はバックエンド起動時に自動作成されるため、データベースは空のままでよい （backend/database.pyのAUTO_MIGRATE）。
Docker Desktopのエンジンが起動していない場合: docker psがerror during connect ... dockerDesktopLinuxEngineで失敗する。 Docker Desktopアプリ（C:\Program Files\Docker\Docker\Docker Desktop.exe）を起動し、 エンジンの初期化（1分ほど）を待ってから再度dockerコマンドを実行する。

4.2 ローカルPostgreSQLを使う場合（未検証）

Dockerが使えない端末向けの代替手段。keirekiの参考資料_環境構築手順.html 4.2節と同じ手順 （winget install → CREATE ROLE / CREATE DATABASE）で動くと想定されるが、本プロジェクトではまだ実際に試していない。 試した場合は結果をこの節に追記すること。

5. .env 設定リファレンス

リポジトリルートの.env.exampleをコピーして.envを作る。Git管理外のため自由に変更してよい。

キー既定値説明
DB_MODEautoDBの用意方法（現状dockerのみ検証済み。start.batによる自動切り替えは未実装）
DB_PORT55433PostgreSQLの待ち受けポート
BACKEND_PORT8020FastAPI/uvicornのポート
FRONTEND_PORT5180Viteのポート。使用中の場合はViteが自動で次の空きポートに割り当てる
DEV_AUTH1開発用ログイン（Google認証の代替）を有効化する。GOOGLE_CLIENT_IDを設定すると自動的に無効になる

その他（ANTHROPIC_API_KEY等のAI機能・Slack通知・Supabase関連）はローカル開発では未設定でよい。詳細は.env.example内のコメントを参照。

6. 起動と動作確認

start.batはまだ無いため、次の3つを個別のターミナルで起動する。

# 1. DB（初回作成済みなら start でよい）
docker start manabi-db

# 2. バックエンド
cd backend
.venv\Scripts\python seed.py      # 初回のみ。usersが空のときだけ投入される
.venv\Scripts\python main.py      # http://localhost:8020

# 3. フロントエンド（別ターミナル）
cd frontend
npm run dev                       # http://localhost:5180

7. トラブルシューティング

T-1: Docker Desktopのエンジンが起動しない

原因対処
Docker Desktopアプリを起動していないC:\Program Files\Docker\Docker\Docker Desktop.exeを起動し、初回は1分ほど待つ
WSL2が無効管理者権限でwsl --install --no-distributionを実行しWindowsを再起動する

T-2: フロントエンドから/api/...が404になる

原因対処
バックエンドが起動していない、またはvite.config.tsのプロキシ先ポートが.envのBACKEND_PORTとずれているバックエンドの起動確認（6.1節）。それでも直らない場合はfrontend/vite.config.tsのproxy設定を確認する

T-3: ポートが使用中で起動しない

ポート対処
フロントエンド（5180）Viteが自動で次の空きポートに割り当てる。起動ログに表示されたURLを開く
バックエンド（8020）.envのBACKEND_PORTを変更する
DB（55433）.envのDB_PORTを変更し、コンテナも同じポートで作り直す
