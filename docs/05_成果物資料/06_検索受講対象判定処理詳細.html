6. 検索・受講対象判定処理詳細

6.1 A-14 教材一覧・検索

実装はrouters/materials.py。指定された条件のみをANDで結合する。status='published'かつis_archived=falseの教材のみを対象とし、下書きはS-14（教材編集：教材一覧）側の別クエリで扱う。実装済み（2026-08-28、S-03）。is_archived=false条件は当初漏れており、アーカイブ（F-30、statusを変更せずis_archivedのみを立てる仕様）済みの教材が一覧に表示され続ける不具合があったため追加した（2026-08-28）。

実装時の簡略化（F-26未実装のため）: F-26教材のプロジェクト間共有（T-22 material_project_shares）は本書の時点でも未実装のため、以下の下線部の共有経由の判定は今回対象外とした。project_idはmaterials.project_idの一致のみ、my_assignments_onlyは5.3節の2条件（プロジェクトの現役メンバー・個人指定の配信。2026-08-28にF-26複製モデル採用に伴い3条件から簡素化済み）で判定する。F-26は複製モデルのため、共有先の教材は複製後に独自のproject_idを持つ通常の教材として扱われ、本節の共有経由判定（下記SQLのコメント付き行）は実装対象外となった。下記の共有経由判定は初期の参照共有モデル検討時の名残であり、F-26着手時に本節ごと見直すこと。
  • キーワードq: タイトル（materials.title）／概要（description）／目次の見出し（material_nodes.title）に対するILIKE '%q%'の部分一致（OR結合）
  • tags（複数可・OR条件）: materials.tags（JSONB配列）が指定タグのいずれかを含むかをtags ?| $1::text[]（JSONB「いずれかを含む」演算子）で判定する（当初はAND条件〔すべて含む〕で設計していたが、実装後にユーザーからOR条件の方が使いやすいとの指摘を受けて変更した。2026-08-28）
  • project_id: 指定時はそのプロジェクトの教材のみ（本来はそのプロジェクトへstatus='accepted'で共有された教材も含める仕様だが、F-26未実装のため現状は対象外）
  • required: 指定時、当該教材のassignments行にrequiredが一致する行が1件以上あるかで判定
  • incomplete_only: リクエストユーザーのenrollment_progress（T-12）がstatus != 'completed'または存在しない教材のみに絞る
  • my_assignments_only: 5.3節のrequire_material_accessの2条件（プロジェクトの現役メンバー・個人指定の配信）のいずれかを満たす教材のみに絞る
SELECT m.id, m.title, m.description, m.tags, m.project_id, p.name AS project_name,
       (SELECT COUNT(*) FROM material_nodes n WHERE n.material_id = m.id AND n.kind = 'chapter') AS chapter_count,
       (SELECT COUNT(*) FROM material_nodes n WHERE n.material_id = m.id AND n.kind = 'page') AS page_count,
       m.updated_at
FROM materials m
JOIN projects p ON p.id = m.project_id
WHERE m.status = 'published'
  AND m.is_archived = false
  AND ($1::text IS NULL OR
       m.title ILIKE '%' || $1 || '%' OR
       m.description ILIKE '%' || $1 || '%' OR
       EXISTS (SELECT 1 FROM material_nodes n
                WHERE n.material_id = m.id AND n.title ILIKE '%' || $1 || '%'))
  AND ($2::text[] IS NULL OR m.tags ?| $2)                 -- tags（OR条件）
  AND ($3::bigint IS NULL OR m.project_id = $3
       OR EXISTS (SELECT 1 FROM material_project_shares s
                   WHERE s.material_id = m.id AND s.shared_to_project_id = $3
                     AND s.status = 'accepted'))            -- project_id（共有先も含む）
ORDER BY m.updated_at DESC
LIMIT $4 OFFSET $5;

6.2 A-39 マイ学習の集計ロジック

実装はrouters/learning.py。実装済み（2026-08-31、S-02）。5.3節のrequire_material_accessと同じ2条件のOR（プロジェクトメンバーシップ／個人指定の配信。2026-08-28にF-26複製モデル採用に伴い3条件から簡素化済み。6.2節は当初3条件のまま記述が古くなっていたため、S-16着手時の見直しで本節も合わせて修正した）で対象教材を求め、必修（assignments.required=trueの行が1件以上ある）／任意に分類して返す。

  1. 対象教材ID集合を、プロジェクトメンバーシップ（5.3節条件1）・個人指定（条件2）のUNIONで求める
  2. 任意教材のうち、所属プロジェクトが全社Wiki（is_company_wide=true）のものは、さらにT-30 my_learning_registrationsに本人の登録行が存在する場合のみ残す（F-31、基本設計書v1.38）。招待制プロジェクトの任意教材はこの絞り込みを適用しない（プロジェクトメンバーシップのみで表示）。必修教材（assignments.required=true）はどちらの場合も登録有無を問わず常に含める。
  3. 各教材についてT-12 enrollment_progressをLEFT JOINし、status・completed_node_idsから進捗率（completed_node_idsの要素数 ÷ 教材の全ページ数）を算出する
  4. next_actionを決定する: 進捗なし→"start"、status='in_progress'→"resume"、status='completed'かつ再受験可→"review"
  5. 必修教材はdue_at昇順（NULLS LAST）、任意教材はupdated_at降順でソートして返す
  6. 「期限が近い必修教材」（S-02強調表示）は、due_atが7日以内かつstatus != 'completed'の教材として抽出する
  7. 「学習履歴」（F-31）: 上記の必修/任意一覧とは別に、登録有無を問わずenrollment_progressの行が存在する（着手済みの）教材を横断的に返す絞り込みも用意する。クエリhistory=trueで切り替え、この場合は必修/任意に分類せずitems1本のフラットな配列として返す（過去に参加していたプロジェクトを離任した後でも履歴として残るよう、5.3節の受講対象判定を経由しない）。

next_actionの判定について: 「必修は"復習する"、任意は"反復演習する"」というボタン文言の出し分け（S-02画面モックアップ）は、バックエンドのnext_actionには反映せず、フロントエンド側でnext_action==='review'とrequiredの組み合わせから決定する（バックエンドは受講状況の抽象的な区分のみを返し、表示文言はフロントエンドの責務とする方針）。

6.4 A-45/A-46 受講状況ダッシュボードの集計

実装はrouters/dashboard.py。scopeパラメータが"company"なら全社員・全教材、"project:{id}"なら当該プロジェクトの現役メンバー（status='active' AND left_at IS NULL）かつ当該プロジェクトの配信設定を対象に集計する。

-- 対象範囲内の必修受講率（scope=project:{id} の例。$1=project_id）
WITH target_users AS (
    SELECT user_id FROM project_memberships
     WHERE project_id = $1 AND status = 'active' AND left_at IS NULL
),
target_assignments AS (
    SELECT a.material_id, a.due_at, a.id AS assignment_id
      FROM assignments a
     WHERE a.scope_type = 'project' AND a.scope_id = $1 AND a.required = true
)
SELECT ta.material_id,
       COUNT(tu.user_id) AS target_count,
       COUNT(ep.user_id) FILTER (WHERE ep.status = 'completed') AS completed_count,
       COUNT(qa.id) FILTER (WHERE qa.passed = true) AS pass_count
  FROM target_assignments ta
  CROSS JOIN target_users tu
  LEFT JOIN enrollment_progress ep
         ON ep.material_id = ta.material_id AND ep.user_id = tu.user_id
  LEFT JOIN LATERAL (
         SELECT * FROM quiz_attempts
          WHERE material_id = ta.material_id AND user_id = tu.user_id
            AND mode = 'graded' AND submitted_at IS NOT NULL
          ORDER BY attempt_no DESC LIMIT 1
       ) qa ON true
 GROUP BY ta.material_id;

未受講者一覧（A-46）は上記のtarget_usersからenrollment_progress.status != 'completed'（またはenrollment_progress行が存在しない）ユーザーを抽出し、due_atを付与して返す。

6.5 A-44 誤答問題抽出出題のロジック

  1. scope='material': 当該教材の設問のうち、リクエストユーザーの直近回答（answersをquestion_idごとにcreated_at降順で1件取得）がis_correct=falseのもの
  2. scope='all': 全教材を対象に同様の条件で抽出する（受講対象外の教材の設問は含めない。5.3節の判定を教材ごとに適用）
  3. 正答率50%未満の設問（全受講者のanswers集計）も対象に含める: SELECT question_id FROM answers GROUP BY question_id HAVING AVG(is_correct::int) < 0.5
  4. 抽出結果をmode='practice', practice_kind='wrong_only'のquiz_attemptsとして作成し、question_orderに対象設問IDを記録する。type='score_log'の設問はそもそも正誤の概念を持たないため抽出対象から除外する。practice_kind='wrong_only'を含む部分ユニークインデックスへのON CONFLICT DO UPDATEで、同一抽出条件の未提出試行があれば取得し直す（二重クリック対策。反復演習の'repeat'と同じmode/scope_node_idだがpractice_kindで区別するため衝突しない。2026-08-31修正、3.3節T-13参照）

6.6 提出時の進捗更新（T-12 enrollment_progress）

A-41（回答保存）の都度、mode='graded'の試行に対する回答である場合のみ、当該ページのnode_idをcurrent_node_idに設定し、statusが'not_started'であれば'in_progress'に更新してstarted_atを設定する（2026-08-31修正: 当初はmodeを問わず常に更新していたため、反復演習・誤答のみ抽出（mode='practice'）で回答すると本来のgraded進行の「続きから受講」再開位置を意図せず書き換えてしまう不具合があった）。A-42（提出）でmode='graded'かつmaterials.attempt_scope='material'の場合、提出済みページのnode_idをcompleted_node_idsへ追加し、全ページが含まれたらstatus='completed', completed_at=now()とする。attempt_scopeが'material'以外の場合は、当該scope_node_id配下のページのみをcompleted_node_idsに追加し、教材全体のstatusは「全ての受験単位が合格しているか」を都度再計算して決定する。mode='practice'の提出（A-42）はこの更新自体を行わない（`submit_attempt`がif attempt["mode"] == "graded":のときのみ_update_enrollment_progressを呼ぶ、既存実装のまま）。
