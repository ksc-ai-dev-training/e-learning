8.2 非同期ジョブの実現方式

基本設計書9.2節の方針（Uvicorn単一プロセス内、Redis/Celery等の別プロセス基盤は導入しない）を実装コードで示す。

# backend/routers/materials.py（F-21の例。他の非同期AI機能も同型）
@router.post("/materials/{material_id}/ai-insights", status_code=202)
async def request_ai_insights(material_id: int, user: User = Depends(require_material_editor(...))):
    row = await conn.fetchrow(
        """INSERT INTO ai_material_insights (material_id, requested_by, requested_at)
           VALUES ($1, $2, now()) RETURNING id""",
        material_id, user.id)
    asyncio.create_task(run_ai_insights_job(row["id"], material_id))
    return {"status": "pending", "job_id": row["id"]}

async def run_ai_insights_job(insight_id: int, material_id: int):
    try:
        stats = await aggregate_question_stats(material_id)       # 6章相当の集計
        survey_stats = await aggregate_survey_stats(material_id)  # 受験後アンケート集計（設置時のみ）
        result = await ai_client.analyze_material_insights(stats, survey_stats)
        await conn.execute(
            """UPDATE ai_material_insights
                  SET weak_questions = $1, suggestions = $2
                WHERE id = $3""",
            json.dumps(result["weak_questions"]), result["suggestions"], insight_id)
    except Exception:
        logger.exception("ai_insights_job_failed", extra={"insight_id": insight_id})
        # 内容カラムはNULLのまま残す。行自体は削除しない（学習記録は失われない）
  • 取得（ポーリング）: フロントエンドはA-35/A-43/A-49/A-52をSWRのrefreshInterval（既定3秒）で呼び出し、結果（内容カラムが非NULL）が現れるまでポーリングする
  • 失敗時のリトライ: ai_client.pyの呼び出し関数内で指数バックオフ（1秒→2秒→4秒）により最大3回リトライする。全て失敗した場合も上記のとおり内容カラムはNULLのまま残し、構造化ログにエラーを記録する（9章）
  • フロントエンドの待機表示: 応答が一定時間（目安3分）無い場合に「時間がかかっています」の案内を表示し、再試行操作（同一APIの再呼び出し）を可能にする

8.3 スタックジョブ・スイープの実装（job_sweep.py）

基本設計書9.2節が定める「起動時＋5分ごと」の復旧処理を実装する。main.pyのlifespanイベントから起動する。

# backend/job_sweep.py
STUCK_THRESHOLD = timedelta(minutes=10)
SWEEP_INTERVAL = timedelta(minutes=5)

async def sweep_stuck_jobs():
    cutoff = datetime.now(timezone.utc) - STUCK_THRESHOLD

    # T-16〜T-18: requested_at が古く、内容カラムが未設定の行
    for insight in await conn.fetch(
            """SELECT id, material_id FROM ai_material_insights
                WHERE requested_at < $1 AND suggestions IS NULL""", cutoff):
        asyncio.create_task(run_ai_insights_job(insight["id"], insight["material_id"]))

    for feedback in await conn.fetch(
            """SELECT id, user_id FROM ai_personal_feedback
                WHERE requested_at < $1 AND content IS NULL""", cutoff):
        asyncio.create_task(run_ai_personal_feedback_job(feedback["id"], feedback["user_id"]))

    for report in await conn.fetch(
            """SELECT id, scope_type, scope_id FROM ai_org_reports
                WHERE requested_at < $1 AND content IS NULL""", cutoff):
        asyncio.create_task(run_ai_org_report_job(report["id"], report["scope_type"], report["scope_id"]))

    # T-14: submitted_at が古く、ai_score_pct が未設定の記述式・code回答（grading_mode='ai'のみ対象）
    for answer in await conn.fetch(
            """SELECT a.id, a.attempt_id, a.question_id FROM answers a
                 JOIN quiz_attempts qa ON qa.id = a.attempt_id
                 JOIN questions q ON q.id = a.question_id
                WHERE qa.submitted_at < $1 AND a.ai_score_pct IS NULL
                  AND q.type IN ('free_text', 'code')
                  AND COALESCE(q.grading_mode,
                      (SELECT grading_mode FROM materials WHERE id = qa.material_id)) = 'ai'""",
            cutoff):
        asyncio.create_task(run_ai_grading_job(answer["id"], answer["attempt_id"], answer["question_id"]))

async def start_sweep_loop():
    await sweep_stuck_jobs()   # 起動直後に1回実行
    while True:
        await asyncio.sleep(SWEEP_INTERVAL.total_seconds())
        await sweep_stuck_jobs()

# main.py
@asynccontextmanager
async def lifespan(app: FastAPI):
    await database.connect()
    sweep_task = asyncio.create_task(job_sweep.start_sweep_loop())
    yield
    sweep_task.cancel()
    await database.disconnect()
再実行の重複起動に対する耐性: スイープが再スケジュールしたジョブと、たまたま同時に処理が続行していた元のジョブが両方完了すると、同じ行へ2回UPDATEが走る可能性がある。内容カラムへの書き込みはUPDATE ... WHERE id = ? AND (対応する内容カラム) IS NULLという条件を必ず付けることで、後勝ちではなく先着1回のみ反映させ、2重実行によるAPIコストの記録漏れ・不整合を防ぐ（2回目のUPDATEは0件更新で終わるが、T-19へのログ記録自体は2回分行われうる点は許容する。学習記録の欠落より二重課金の可能性の方が実害が小さいため）。

8.4 モデル選択の実現方式

「画面設定 > 環境変数 > 既定値」の優先順位で解決する（基本設計書9.4節）。

DEFAULT_MODEL = "claude-sonnet-5"
AVAILABLE_MODELS = ["claude-sonnet-5", "claude-opus-5", "claude-haiku-4-5"]

async def get_model() -> str:
    row = await conn.fetchrow("SELECT value_text FROM app_settings WHERE key = 'ai_model'")
    if row is not None and row["value_text"] in AVAILABLE_MODELS:
        return row["value_text"]
    env_model = os.environ.get("ANTHROPIC_MODEL")
    if env_model in AVAILABLE_MODELS:
        return env_model
    return DEFAULT_MODEL

全5機能（F-08, F-20〜F-23）で同一のモデル設定を共有し、機能ごとの個別設定は持たない（S-10の画面が単一のプルダウンであるため）。

8.5 AI利用ログ・コスト計算

ai_client.pyは呼び出し完了時（成功・失敗いずれも）にT-19へ1行記録する。

# 単価表（USD / 1Mトークン）。Anthropicの公開単価改定時に更新する。
# 下表の数値はプレースホルダであり、実装時にAnthropic公式の最新料金表で確認・置き換えること。
MODEL_COSTS = {
    "claude-sonnet-5": {"input": 3.00, "output": 15.00},
    "claude-opus-5":   {"input": 15.00, "output": 75.00},
    "claude-haiku-4-5": {"input": 0.80, "output": 4.00},
}
USD_TO_JPY = 150  # 固定レート。概算表示のための定数（Keirekiと同方針）

def estimate_cost_jpy(model: str, input_tokens: int, output_tokens: int) -> float:
    costs = MODEL_COSTS.get(model, MODEL_COSTS[DEFAULT_MODEL])  # 未知モデルは既定モデル単価で概算
    usd = (input_tokens * costs["input"] + output_tokens * costs["output"]) / 1_000_000
    return round(usd * USD_TO_JPY, 6)

記録タイミング: 呼び出し完了直前にT-19へINSERTする。失敗（3回リトライ後も失敗）した場合は記録しない（実施できた利用の傾向把握を主目的とするため）。

8.6 構造化出力スキーマ・プロンプト設計（機能別）

F-08 教材AIレビュー（A-32）

Claude APIのツール呼び出し（tool use）で構造化されたJSONを受け取る。送信データは教材本文（サニタイズ前の原文でよい。AIへの送信はXSS対策の対象外）・問題定義（基本設計書9.5節「送信データ範囲」に対応）。

review_tool_schema = {
    "name": "submit_review",
    "input_schema": {
        "type": "object",
        "properties": {
            "findings": {
                "type": "array",
                "items": {
                    "type": "object",
                    "properties": {
                        "location": {"type": "string"},        # 章・ページのタイトルで示す
                        "severity": {"type": "string", "enum": ["info", "warning"]},
                        "issue": {"type": "string"},            # 指摘内容
                        "suggestion": {"type": "string"},       # 改善提案
                    },
                    "required": ["location", "severity", "issue"],
                },
            }
        },
        "required": ["findings"],
    },
}

システムプロンプトの要旨: 「教材の説明不足・記述の分かりにくさ・問題と教材内容の不整合を指摘するレビュアーとして振る舞う。指摘は具体的な章・ページ名で場所を示す。改善提案は任意（無ければsuggestionを省略）」。

F-20 AI記述式採点・講評（A-42内部から起動）

送信データ: 回答内容（コード記述式は提出コード本文＋code_language）・出題の模範解答/採点基準（scoring_criteria）。基本設計書5.20節の講評スタイル（feedback_style）・採点コンテキスト（ai_context）をシステムプロンプトに反映する。

grading_tool_schema = {
    "name": "submit_grading",
    "input_schema": {
        "type": "object",
        "properties": {
            "correct": {"type": "boolean"},
            "score_pct": {"type": "number"},         # 0-100。部分点は認めず0または100を基本とする（正答率算出は正解数ベースのため）
            "reasoning": {"type": "string"},           # 判定根拠
            "improvement_suggestions": {"type": ["string", "null"]},  # コード記述式のみ
        },
        "required": ["correct", "score_pct", "reasoning"],
    },
}

feedback_styleに応じたシステムプロンプトの切替:

feedback_styleプロンプト指示
show_answer（既定）模範解答の要点と講評を明示的に提示する
review_only正解そのものは提示せず、コード記述式なら問題箇所の指摘のみを行う
hint_only正解を見せず、考え方のヒントのみを示す

materials.ai_contextが設定されている場合は「以下は本教材固有の採点方針である: {ai_context}」としてシステムプロンプト末尾に追記する。

F-21 AIつまずき分析・教材改善提案（A-34）

送信データ: 設問ごとの正答率・誤答傾向の集計値（個々の受講者を特定できる回答・氏名は送信しない）。受験後アンケート設置時は評価点平均・自由記述のテキスト群も含める。

insight_tool_schema = {
    "name": "submit_insight",
    "input_schema": {
        "type": "object",
        "properties": {
            "weak_questions": {
                "type": "array",
                "items": {
                    "type": "object",
                    "properties": {
                        "question_id": {"type": "integer"},
                        "correct_rate_pct": {"type": "number"},
                        "trend": {"type": "string"},   # 誤答の傾向（自由記述）
                    },
                },
            },
            "suggestions": {"type": "string"},   # 教材改善提案（Markdown形式のテキスト）
        },
        "required": ["weak_questions", "suggestions"],
    },
}

F-22 AI個人フィードバック（A-51）

送信データ: 対象者本人の回答傾向データ（正誤・分野別集計）。氏名・メールアドレスは送信せず、宛先としての表示はフロントエンドで付与する。type='score_log'の設問がある場合はスコア推移（時系列）も入力に加え、推移コメント（例:「タイピング練習のスコアが着実に上がっています」）を生成させる。出力は構造化せず自由記述テキスト（content）とする。

F-23 AI組織レポート生成（A-48）

送信データ: プロジェクト単位・全社単位の集計データ（受講率・合格率等の数値のみ。個人が特定できる粒度のデータは送信しない）。出力は自由記述テキスト（要約＋示唆を含むレポート、content）とする。

8.7 ai_client.py 共通呼び出し設計

  • 構造化出力: F-08・F-21はツール呼び出しで構造化JSONを受け取り、パース失敗時のフォールバック処理は挟まない（Claude APIのtool useは指定スキーマへの準拠が保証されるため）。F-20は同様にツール呼び出しを用いる。F-22・F-23は自由記述テキストで受け取る。
  • タイムアウト・リトライ: 1回の呼び出しにつきタイムアウト60秒、指数バックオフで最大3回リトライする（8.2節）。
  • モデル解決・ログ記録: 8.4節のモデル解決、8.5節のT-19記録はai_client.py内で一元的に行い、各機能の呼び出し元（materials.py, learning.py, dashboard.py, reports.py）はモデル名やログ記録を意識しない。
  • 例外処理: Claude API呼び出しの例外はlogger.exceptionでサーバーログに記録し、利用者にはAPIキーやエラー詳細を含まない汎用メッセージのみ返す（同期呼び出しのF-08は502、非同期呼び出しは8.2節のとおり内容カラムをNULLのまま残す）。
