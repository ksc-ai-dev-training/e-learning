1. はじめに

1.1 背景

当社では、新人研修・オンボーディング・各種社内教育・個人の自己学習が、それぞれ個別の資料や運用で行われている。教材はGoogleドライブ上のファイルとして散在し、誰が何をどこまで学んだかは記録されていない。そのため、教育の実施状況を把握できず、教材が理解されているかどうかを確かめる手段もない。教材の改善は作成者の感覚に頼っている状態である。

一方、当社ではClaude Codeの全社活用を進めており、教材そのものをAIで効率よく作成できる環境が整いつつある。作った教材を配り、学習状況を記録し、その結果を分析して教材を改善するという一連の流れを支える仕組みが必要となっている。

1.2 目的

教材の作成から学習・記録・分析・改善までを一つのシステム「社内e-learningシステム（コードネーム: Manabi）」で扱えるようにすることを目的とする。特に、Claude Codeで作成した教材をそのまま登録・改訂でき、AIによる分析結果をもとに教材を改善していく循環を実現することを重視する。

1.3 本書の位置づけ

本書は、発注者が本システムに対して「何をしてほしいか」を要求として示すものである。要求をどのように実現するかの要件定義・設計は、後続の要件定義書・基本設計書にて行う。本書では実現方式・画面構成・データ構造は規定しない。

1.4 本システムが目指す循環

本システムの中心にあるのは、以下の循環である。入口（教材作成）と出口（分析）の両方でAIを活用し、教材が使われるほど良くなっていく状態を目指す。

青枠の①②⑥がAIを活用する工程。⑥の分析結果が①に戻り、教材が使われるほど良くなっていく。

2. システム化の対象と範囲

2.1 対象業務

  • 教材・問題の作成と登録・改訂
  • 教材の配信対象の設定（全社・プロジェクト・部署・個人）
  • 受講（教材の閲覧、問題への回答）
  • 学習状況・回答内容の記録
  • 必修教育の受講状況の管理（期限・未受講者の把握・催促）
  • 学習結果の分析とレポート作成
  • 社員による自主的な教材の作成・共有

2.2 対象外

以下は本システムの対象外とし、システム化の範囲に含めない。

  • 人事評価・査定（学習実績を評価に直接用いることは想定しない）
  • 個人目標管理・1on1（別途検討中の社内成長支援プラットフォームの領域）
  • 社外向けの教育コンテンツ配信
  • 資格取得の申請・受験料精算などの事務手続き
  • 外部e-learningサービスの受講管理（外部サービスの受講記録を取り込むことは行わない）

3. 要求事項

3.1 機能要求（教材の作成・登録）

要求ID要求説明
REQ-F-01 教材と問題を登録・修正できること 教材（説明文・図・資料）と、その理解度を確認する問題を登録し、後から修正できること。教材は単元・コース等のまとまりとして構成でき、学習する順序を示せること。
REQ-F-02 Claude Codeから教材・問題を登録・修正できること 本システムの最も重視する要求。Claude Codeで作成した教材を、画面での再入力なしにシステムへ反映できること。具体的には次の4点を満たすこと。
  • 教材・問題をテキスト形式（Markdown等）で記述できること
  • 手元のファイルの登録・更新が、画面操作を介さず実行できること
  • システム上の既存教材を取得して修正し、システムへ戻せること（往復できること）
  • 教材の改訂履歴が残り、いつ誰が何を変更したかを追えること
REQ-F-03 動画・スライド等のファイルを教材として扱えること テキストと画像に加え、動画・スライド・PDF等をアップロードして教材に含められること。外部サービス上の資料へのリンクも教材として扱えること。
REQ-F-04 社員が自分で教材を作成・共有できること 教育担当者だけでなく、社員が学んだことを教材として登録し、他の社員に共有できること。社内の学びが個人に閉じず蓄積されていくことを狙いとする。
REQ-F-05 公開前にAIが教材をレビューできること 教材を公開する前に、AIが内容を確認して問題点や改善点を作成者に示せること。説明の不足、記述の分かりにくさ、問題と教材内容の不整合などが対象となる。人による承認を挟まずに教材の質を高められることを狙いとする。指摘に従うかどうかは作成者が判断できること。

3.2 機能要求（配信・受講）

要求ID要求説明
REQ-F-06 会社全体・プロジェクト・部署・個人を単位として教材を割り当てられること 「全社員が対象」「特定プロジェクトのメンバーが対象」「特定部署が対象」「特定の個人が対象」といった単位で教材の受講対象を指定できること。組織の異動やプロジェクトの参画・離任があっても、対象者が適切に保たれること。
REQ-F-07 必修と任意を区別して扱えること 会社が受講を課す必修教材と、社員が自ら選んで学ぶ任意教材を区別できること。受講者が「自分がいま何を受けなければならないか」を把握できること。
REQ-F-08 必修教材の期限を設定し、未受講者を把握・催促できること 必修教材に受講期限を設定でき、期限までに受講していない者を管理者が把握できること。また、対象者本人へSlackで受講を促せること。未受講の検知ができて初めて必修教育の運用が成り立つため、重要な要求とする。
REQ-F-09 合否判定と再受験ができること 問題に合格基準を設定して合否を判定できること。不合格の場合に再受験ができ、再受験の可否や回数を教材ごとに定められること。
REQ-F-10 選択式・記述式の問題に回答できること 単一選択・複数選択などの選択式に加え、文章で答える記述式の問題を出題・回答できること。
REQ-F-11 中断・再開ができること 学習を途中で中断しても、次回に続きから再開できること。業務の合間に少しずつ受講することを想定する。
REQ-F-12 問題を何度でも繰り返し解けること 合否判定を目的とする受験（REQ-F-09）とは別に、習熟を目的として同じ問題を回数の制限なく繰り返し解けること。この繰り返しの結果は合否には影響しないこととし、受講者が気兼ねなく反復できること。出題の順序や選択肢の並びを毎回変えられることが望ましい。
REQ-F-13 間違えた問題だけを集めて出題できること 受講者が過去に誤答した問題や、正答率の低い問題だけを集めて出題できること。一度で正解できた問題を繰り返し解く必要がなく、苦手な箇所に絞って学習できることを狙いとする。対象とする範囲（特定の教材内か、これまで学習した全教材か）を受講者が選べること。

3.3 機能要求（記録・分析・レポート）

要求ID要求説明
REQ-F-14 学習状況と回答内容を記録できること 誰がどの教材をいつ受講し、どこまで進み、各設問にどう回答したかを記録すること。分析の材料となるため、正誤だけでなく回答内容そのものを残すこと。
REQ-F-15 受講状況を組織単位で確認できること 管理者・部署長・PMが、担当範囲の受講状況（受講率・合格率・未受講者）を確認できること。
REQ-F-16 AIが記述式の回答を採点し講評できること 記述式の回答について、AIが採点し、根拠を伴う講評を返せること。採点結果は人が確認・修正できること。
REQ-F-17 AIがつまずきを分析し、教材の改善点を提案できること 正答率の低い設問や誤答の傾向から「受講者がどこを理解できていないか」を分析し、教材のどこをどう直すべきかを提案できること。REQ-F-02のClaude Code連携と組み合わせ、分析結果をもとに教材を改訂する循環を成立させることを狙いとする。
REQ-F-18 AIが受講者個人にフィードバックできること 受講者ごとの回答傾向から、理解が不足している点や次に学ぶとよい教材を本人に示せること。
REQ-F-19 AIが組織単位のレポートを作成できること 部署・プロジェクト単位の学習状況や習熟度の傾向を、管理者が読める形のレポートとしてまとめられること。数値の一覧だけでなく、状況の要約と示唆を含むこと。

3.4 非機能要求

要求ID要求説明
REQ-N-01 Google認証により当社のGoogleアカウント保有者しか利用できないこと 当社はGoogle Workspaceを利用している。追加のID管理を発生させず、許可ドメインのGoogleアカウントを持つ利用者以外はアクセスできない仕組みとすること。
REQ-N-02 役割により操作範囲を制御できること 受講者・教材作成者・部署長/PM・管理者といった役割に応じて、操作できる範囲・参照できる他者の学習状況の範囲を制御できること。
REQ-N-03 学習記録が本人の不利益に使われない扱いとすること 学習状況は成長支援のための情報であり、人事評価の材料ではない。誰がどこまで参照できるかを適切に定め、受講者が萎縮せず学べる状態とすること。
REQ-N-04 スマートフォンからも学習できること 移動中や業務の合間に受講できるよう、主要な学習操作がスマートフォンの画面で無理なく行えること。
REQ-N-05 AIの応答待ちで学習が妨げられないこと AIによる採点・分析には時間がかかる場合がある。受講者が長時間待たされたり、分析処理の失敗で学習記録が失われたりしないこと。
REQ-N-06 既存システム（LCC CRM）の技術構成を踏襲すること 社内で運用実績のあるLCC CRMと同一の技術スタック・構成とすることで、保守要員のスキル共通化と運用ノウハウの再利用を図ること。

4. 制約条件

  • 技術構成: 既存システムLCC CRMの技術構成を踏襲すること（REQ-N-06）。独自の技術選定は行わない。
  • 認証基盤: 認証はGoogleアカウント（許可ドメイン: kogasoftware.com）を前提とすること。
  • AI利用: AIによる採点・分析は外部のAI APIの利用を前提とする。利用にあたっては費用が発生すること、および社内情報を送信することを考慮すること。
  • 通知手段: 利用者への通知はSlackとし、メールによる通知は行わない。当社では業務連絡にSlackを利用しており、メールは誤送信時の影響が大きく、宛先を誤れば社外へ届きうるためである。
  • 大容量ファイル: 動画・スライドを扱うため、無料枠のストレージ容量やアップロード可能なファイルサイズの上限が制約となる。扱えるファイルの種類・サイズには上限を設けてよい。
  • 利用規模: 利用者は200名程度。全社必修教材の配信直後にアクセスが集中する。
  • 組織情報: 部署・プロジェクトの構成情報は現時点で本システムが参照できる形では存在しない。本システム内で保持するか他から取り込むかは、要求定義フェーズで整理する。

5. 前提条件・留意事項

  • 本システムは社内利用を前提とし、社外への公開は行わない。
  • 既存の研修資料（本フォルダのHTML資料等）を教材として取り込むかは、別途協議する。
  • 社員が作成した教材の公開範囲・品質の担保方法（公開前の承認要否等）は、要求定義フェーズで整理する。
  • 受講記録をISMS等の外部監査の証跡として用いることは、現時点では想定しない。将来必要となった場合は、記録の保存期間や出力形式を改めて検討する。
  • 別途検討中の社内成長支援プラットフォーム（個人目標・1on1）との連携は、現時点では行わない。将来の課題とする。
研修での進め方について
本書は「何をしてほしいか」までを示すものであり、画面構成・データ構造・実現方式は意図的に記載していない。それらをどう決めるかが要求定義以降の作業となる。特にREQ-F-02（Claude Code連携）とREQ-F-17（AIによる教材改善提案）は本システムの特徴となる部分であり、どう実現するかをよく検討すること。判断に迷う点は、まずAIに相談し、それでも決まらないものはSlack「ai開発研修」チャンネルで質問すること。

6. 用語定義

教材学習の対象となるコンテンツ。説明文・図・動画・スライド等を含む。
問題教材の理解度を確認するための設問。選択式と記述式がある。
コース / 単元教材をまとまりとして構成したもの。学習の順序を示す単位。
受講受講者が教材を閲覧し、問題に回答する一連の行為。
受講対象教材を受講すべき者の範囲。会社全体・プロジェクト・部署・個人のいずれかの単位で指定する。
必修教材会社が受講を課す教材。受講期限を設定し、未受講者を把握・催促する対象となる。
任意教材社員が自ら選んで学ぶ教材。個人学習・ナレッジ共有に用いる。
合格基準問題に合格したとみなす条件（正答率等）。

オンボーディング新しく加わった社員が業務を開始できる状態になるまでの一連の教育。
